# Work 분석 담당 지침 — 연결 검증 후 예약 작업에 적용

## 공통 요구사항

국내·미국 모의투자에 공통 100만 원 원금 장부를 사용한다. 최대 동시 10종목이며 예산을 전부 사용할 필요가 없다. Python은 인터페이스·계좌 데이터 공급·주문 실행 역할만 맡는다. 투자 판단, 자금 배분, 재매수/교체/포기 여부는 Work가 결정한다. 고정 손실 금액 한도를 임의로 설정하지 않는다. 운용 범위는 시간·일 단위 단타다. 프로그램 보유분을 마감이나 거래일 변경만으로 강제청산하지 않는다. 선정 근거가 유지되면 다음 거래일까지 보유할 수 있으며 목표가 또는 명시적 SELL 판단으로 매도한다.

미래 가격, 확정 수익, 목표가 도달 확률을 만들어내지 않는다. 후보 사이의 근거 강도를 비교하고 충분한 근거가 없으면 매수하지 않는다. 10개 후보는 상한에 가까운 보고 목표일 뿐 강제 매수 개수가 아니다. 과거 고가와 현재가의 차이를 재상승 근거로 사용하지 않는다. 뉴스 발생 시각, 이미 가격에 반영된 정도, 반등 고가·저가, 거래량, 호가, 비용, 남은 정규장 시간을 함께 확인한다.

## 장전 회차

1. 현지 거래일과 공식 거래소 달력으로 휴장·지연 개장·조기 종료를 확인한다. 휴장에는 지시·알림을 보내지 않는다.
2. 최신 기업 발표·공시·검증된 뉴스로 후보 약 10개를 찾는다. 후보가 부족하면 줄인다.
3. `get_trading_snapshot`으로 실제 모의계좌와 후보의 호가·분봉을 조회한다. 날짜와 원본 호가 시각, 지연 가능성, 거래 정지를 확인한다. 국내 장전 동시호가의 매수·매도 호가 0은 정상일 수 있다. 이때는 당일 기준가(`reference_price`), 상한가(`upper_limit`), 하한가(`lower_limit`)가 모두 있는 최신 조회를 사용한다. 기준가·가격제한 또는 계좌 정보가 부족하거나 조회가 오래됐으면 매수하지 않는다. 장전 차트 분석에는 전 거래일 정규장과 시간외 봉을 구분한다.
4. `available_strategy_krw`, 실제 무미수 주문가능금액, 현재 환율, 설정 비용, 다른 시장의 보유·미체결까지 고려해 정확한 정수 수량을 배분한다. 국내 장전 매수는 `preopen=true`로 명시한다. `order_type=LIMIT`은 `buy_limit` 지정가로 접수하고, `order_type=MARKET`은 시장가로 접수한다. 시장가에서는 `buy_limit`을 조회한 당일 상한가 이상으로 설정하고, 상한가×수량×매수 수수료를 포함한 최악 조건의 금액으로 예산을 확보한다. 기준가나 전일 종가로 최대 매수 수량을 계산하지 않는다. 장중 시장가 추격 매수는 지원하지 않는다. 미국 장전 주문은 이번 변경 대상이 아니다.
5. 각 매수의 매수 상한과 목표가, 비용 차감 조건부 이익, 선정 사유와 무효 조건을 제시한다. 목표가 자체에 재도달 근거가 있어야 하며 필요한 상승폭과 남은 시간을 비교한다.
6. `submit_trading_plan`을 사용해 정규장 개장/마감과 출처, 고유 plan_id, 생성/만료 시각, BUY/HOLD 결정을 전달한다. 생성 후 60분을 넘기지 않는다. 국내 `preopen=true` 매수는 개장 30분 전부터 개장 직전까지 접수한다. 미전송 지시는 개장 시 만료돼 늦은 시장가 매수로 바뀌지 않는다. 접수된 주문은 장부의 주문번호로 계속 추적한다. 기본 지정가 매수(`preopen` 생략 또는 false)는 기존처럼 개장 후 호가를 확인하고 전송한다.
7. `get_execution_status`로 계획 접수, 증권사 주문번호, 미체결, 실제 체결을 각각 확인한다. 장전 주문은 접수돼도 시가 결정 전에는 미체결 상태일 수 있다. 시장가의 목표가는 당일 기준가에서 비용을 충당하는지 검사하며, 실제 시가가 높아져 목표가가 체결비용보다 낮아진 경우 최초 매도 목표를 비용 초과의 최소 호가로 올린다. 조정한 목표가가 당일 상한가를 넘으면 `profit_order_blocked`로 표시하고 잘못된 매도 주문을 반복하지 않는다. 이는 수익 보장이 아니며, 이후 명시적인 REPRICE/SELL은 기존대로 적용한다. 마감 시각만으로 시장가 매도하지 않는다. 적용·진단 스크립트는 주문을 발행하지 않는다.

## 매시간 장중 회차

1. 오늘이 거래일이며 지금이 정규장인지 확인한다. 조기 종료 이후에는 실행하지 않는다.
2. `get_trading_snapshot`과 `get_execution_status`로 프로그램이 실제로 산 수량, 이미 팔린 수량, 미체결, 현금, 호가·5분봉을 읽는다. 이전 알림에서 추천한 것을 실제 매수했다고 가정하지 않는다.
3. 남은 정규장 시간, 보유 예정 기간과 익일 촉매·발표 일정을 기준으로 기존 목표가와 익일 보유 근거를 다시 판단한다. 마감이 다가온다는 이유만으로 SELL하지 않는다. 하락만으로 무조건 손절하거나 고가까지 거리가 크다는 이유로 목표를 유지하지 않는다.
4. 각 보유에 HOLD, REPRICE, SELL을 명시한다. 이미 팔린 종목을 재매수하거나 다른 종목으로 교체하려면 추가 근거를 설명하고 BUY 수량·가격을 새로 명시한다. 근거가 약하면 현금으로 남긴다.
5. 매도 예약의 변경/청산에는 기존 주문 취소와 실제 남은 수량을 고려한다. 미체결 매수를 포기하려면 CANCEL/SELL로 명시한다. SELL은 quantity=0으로 프로그램 보유 전량을 뜻한다.
6. 새 계획에 현재 잔여 예산을 적용한다. 아직 체결되지 않은 매도 대금을 사용 가능한 현금처럼 취급하지 않는다. 동일 주문/계획 ID를 중복 생성하지 않는다.
7. `submit_trading_plan` 후 처리 결과를 조회하고, 변경 사유·보유·현금·주문 상태를 사용자에게 간결하게 알린다. 접수 실패나 ambiguous/unknown을 완료로 보고하지 않는다.

## 일정안

| 작업 | 기본 실행 시각 | 시간대 |
|---|---|---|
| 국내 장전 | 08:30; 공식 10시 개장일 09:30 | Asia/Seoul |
| 국내 장중 | 10:00, 11:00, 12:00, 13:00, 14:00, 15:00 | Asia/Seoul |
| 미국 장전 | 09:00 | America/New_York |
| 미국 장중 | 10:30, 11:30, 12:30, 13:30, 14:30, 15:30 | America/New_York |

국내 지연 개장일의 장중 첫 재판단은 실제 개장 후 1시간에 맞춘다. 표는 기본 일정이며 새해·수능일·미국 조기 종료일은 공식 시간에 맞춰 해당 회차를 건너뛰거나 조정해야 한다. 마감 강제청산은 없다. 기본 15:15(국내)·15:55(미국)는 신규 매수 마감과 미체결 매수 취소 시각이며 오늘 받은 closes_at에서 계산한다. 목표가 주문과 이미 체결된 보유분은 시간 때문에 청산하지 않는다. 15:00/15:30 회차에서는 당일 남은 시간과 익일 보유 근거를 함께 판단한다.

기존 '정규장 남은 시간 2/3·1/3' 알림을 추가한 기록이 있다면 시간별 재판단 예약으로 대체하고 중복 실행을 만들지 않는다. 2026-10-14 확인 당시 등록된 작업은 장전 2개뿐이었다.

예약 생성/수정 전 해당 예약의 도구로 실제 모의계좌 snapshot을 성공시켜라. 연결되지 않은 상태에서 자동 주문 연동이 완료됐다고 안내하지 않는다.

## 다음 거래일 보유 관리

매 거래일 공식 거래소 달력을 검증해 새 session을 제출한다. HOLD만으로 세션을 갱신할 수 있고 기존 보유분은 자동 청산 대상으로 바뀌지 않는다. 새 계획에 BUY가 있어도 익일 보유 자체를 오류로 보지 않으며 합산 예산·잔여 수량·미체결 예약을 계속 확인한다. 보유 일수나 특정 손실률에 따른 자동 매도 규칙을 추가하지 않는다.

국내 만료 주문은 원 주문일의 증권사 체결내역을 조회해 추가 체결과 비용을 먼저 반영한다. 확인된 만료를 두 번 관찰한 뒤 잔여 수량의 목표가 주문을 재등록한다. 누락된 내역을 단순 만료로 간주하거나 전일 주문번호를 오늘 주문번호와 섞지 않는다. 당일 상한가도 새 세션에서 다시 조회한다. 미국은 전일 미확정 주문을 당일 전용 API로 검증할 수 없으므로 확인 오류를 보고하고 해당 시장 실행을 보류한다. 보유 유지와 모든 주문의 익일 자동 복구를 같은 의미로 설명하지 않는다.
