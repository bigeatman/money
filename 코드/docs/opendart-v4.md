# XML 보완과 10개 종목 수집 재개

LG 보고서에는 `<종속기업>`과 `D&O`처럼 표준 XML 파서가 읽지 못하는 본문 표현이 있었습니다. v4는 원본 파일·체크섬을 유지하면서 조회용 구조를 만들 때 해당 표현을 일반 텍스트로 처리합니다. 처리 내역은 `archive_parse_notes`에 기록합니다. 지원하지 못하는 형식은 오류를 숨기지 않고 원문을 보존합니다.

명시한 회사·API만 처리하는 재개 가능한 수집 작업과, 원본 DOCX 검토 영역별 확인 내용·미확인 사유를 DB에 기록하는 인터페이스도 추가했습니다. 자료는 Termux가 직접 다운로드하고 저장합니다.

## Termux에서 실행

기존 v3 설치의 Termux에서 아래 블록을 한 번 실행합니다.

```bash
(
set -e
cd "$HOME/money-work/money/코드"
curl -fL --retry 3 \
  'https://raw.githubusercontent.com/bigeatman/money/codex/opendart-cache/updates/money_dart_v4_20261019.py' \
  -o "$HOME/money_dart_v4_20261019.py"
printf '%s  %s\n' \
  '2278b55c3ad7db1c030acba87e955ac8ea84d3034961df0ac110fd1d20c1c563' \
  "$HOME/money_dart_v4_20261019.py" | sha256sum -c -
python "$HOME/money_dart_v4_20261019.py" "$PWD" --start-plan
)
```

소스·DART DB를 백업하고, 전체 테스트 후 서버를 재시작합니다. 실제 v4 서버를 확인한 뒤 실패한 XML 색인만 로컬에서 다시 생성하고 내장된 10개 종목 수집 계획을 시작합니다. 설정·키·매매 장부는 유지합니다. 기존 15만여 건의 전체 파일 이관은 반복하지 않습니다.

`--start-plan`을 생략하면 코드 갱신·XML 재색인만 하며 자료 수집은 시작하지 않습니다. 완료된 요청과 동일 API·인자의 캐시는 재사용합니다. 원격 변경 확인이 필요한 개별 요청은 `call_dart_api`의 `refresh=true`로 따로 지정합니다.

성공 시 `opendart-v4 / schema_version=2 / configured=true`와 작업 ID `sample_20261019_random10_v1`이 출력됩니다. 수집은 서버 안에서 계속됩니다. 업데이트·재색인, 전체 자료 수집, 검토 결과 기록은 각각 진행 상태를 확인합니다.

## 플러그인 도구

money 플러그인의 도구 정의를 갱신합니다.

| 인터페이스 | 용도 |
| --- | --- |
| `manage_dart_collection` | 계획 시작·재개, 요청별 결과·검토 기록 조회 |
| `record_dart_review` | 확인 내용·근거·미확인 사유를 파일·SHA-256·DB·수정 이력으로 저장 |
| `query_dart_data`의 `view=text` | 문서의 검색어 문맥과 문자 위치 조회 |
| `query_dart_data`의 `view=files` | 원본·내부 파일의 체크섬, 파싱 오류와 보완 방식 조회 |

검토 기록은 assistant의 해석임을 표시합니다. `found`는 확인 내용과 저장된 근거가 필요하며, 미확인·부분 확인·외부 자료 필요·비적용에는 사유가 필수입니다. 자료 없음(`013`), 파일 없음(`014`), 조회 실패, 값 0을 구분합니다. 자료 수집 완료가 투자 검토 완료를 뜻하지 않습니다.

기존 무작위 10개 종목을 유지하고 거래량·가격으로 제외하지 않습니다. 원본 DOCX의 공통 42개·업종 22개·상황 5개를 보존하므로 영역별 결과 기록 대상은 690개입니다. 2023-10-19~2026-10-19 공시 목록의 보고 기간별 자료·정정·원본을 포함합니다. 제공 기간 밖인 API·기간 조합은 계획에 사유를 기록했습니다. 공식 응답 필드가 같은 다중회사 주요계정·주요 재무지표 API는 단일회사 API의 중복이므로 생략했습니다.

## 중단과 재개

요청별 결과를 즉시 DB에 저장합니다. 서버 종료 후에는 명시적으로 작업을 재개합니다. 일일 한도·인증 오류에서는 멈추며, 이를 회사 자료 부재로 간주하지 않습니다. 일반 조회 실패는 기록하고 `retry_failed=true`로 재시도합니다. 다른 회사나 기존 전 종목 큐를 임의로 추가 실행하지 않습니다.

실패한 XML 색인만 다시 생성할 때는 다음 명령을 씁니다. 네트워크 호출은 없습니다.

```bash
python -m money.cli dart-reindex --limit 100 --all
```

`all_ok=false`라면 `unresolved`의 사유를 확인합니다. 원문 파일은 유지됩니다.
