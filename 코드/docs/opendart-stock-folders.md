# 종목별 원본 응답 폴더와 트리

Termux에 이미 저장한 원본을 법인 ID 폴더로 모으고 목록을 조회한다. 파일을 ChatGPT 쪽으로 내보내거나 ZIP 묶음을 전송하는 기능은 추가하지 않는다.

```bash
python -m money.cli dart-query --view files --corp-code 01639508 --limit 100
```

폴더는 `runtime/fundamentals.files/companies/01639508/`이다. `responses/` 아래 API별 하위 폴더에 요청 ID와 체크섬을 포함한 개별 파일을 저장한다. JSON/XML/ZIP/오류/부분 응답의 실제 바이트와 SHA-256을 유지한다. ZIP을 재생성하거나 임의로 압축 해제하지 않는다. 동일 응답을 여러 번 받은 경우 요청별 파일을 유지한다.

`MANIFEST.json`에는 각 요청의 인자·결과·체크섬·출처와 파일 경로가 들어 있다. HTTP 본문이 없는 실패는 파일을 만들지 않고 그 사실을 기록한다. 과거 JSON을 재구성한 자료가 있으면 `legacy/`로 구분하고 원본 HTTP 바이트로 표시하지 않는다. `TREE.json`은 폴더의 전체 파일 경로를 담는다.

MCP는 기존 `query_dart_data`에 `view=files, corp_code=01639508`을 전달한다. `endpoint`는 목록 필터다. 결과의 `next_offset`이 있으면 다음 페이지를 조회한다. 종목 폴더 정리는 기존 보관 자료를 사용하며 DART 호출은 0회다. 이 폴더는 그 회사의 기존 응답 이력을 포함하므로, 지금 새로 실행한 최소 수집 계획의 호출 수와 폴더 파일 수를 혼동하지 않는다.

이미 저장한 공시가 어느 법인의 것인지 판별할 때 요청의 corp_code, 캐시의 법인 연결, 저장된 명시적 수집 계획을 사용한다. 다른 법인 파일을 포함하지 않는다. 누락·변조 파일은 완료로 처리하지 않는다.

## 서버를 종료하지 않는 적용

빌드된 `updates/money_stock_folders_20261019.py`는 알려진 v4 소스 해시 확인, 코드 백업, 소스 적용, 폴더 기능 검사를 한다. 서버나 tmux 세션을 종료하지 않고 API 타임아웃 설정도 변경하지 않는다. `--corp-code 01639508`을 주면 같은 작업에서 해당 폴더를 만들고 조회용 목록을 기존 DB에 저장한다. API 키·설정·매매 장부는 수정하지 않는다.

현재 실행 중인 서버는 이전 코드를 계속 사용한다. **지금 만든 트리는 서버 재시작 없이** 기존 도구로 읽을 수 있다.

```json
{"view":"fields","source_key":"stock-files:01639508","field":"/paths","limit":100}
```

또는 `get_fundamental_evidence(source_key="stock-files:01639508")`를 사용한다. 새 `files+corp_code` 분기는 다음 정상 서버 재시작부터 사용할 수 있다. 목록은 로컬 파일 자료이며 DART가 제공한 기업 사실이 아니다.

수집 완료와 폴더 정리는 별개다. 이 기능이 있다고 69개 검토 영역의 실제 내용 확보나 투자 분석 완료가 보장되는 것은 아니다.
