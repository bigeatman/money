# V7 전체 시장 데이터 수집

V7은 전체 목록에서 시작해 모든 대상 종목의 공통 데이터를 확보한다. 수집과 주문 실행은 다른 스레드에서 수행하며 수집 코드에는 주문·지시 제출 경로가 없다. 상승 판단, 사건 조사, 후보 비교와 실제 BUY/REPRICE/SELL 결정은 Work가 수행한다.

## 전체 범위와 단계

1. 국내는 KOSPI·KOSDAQ·KONEX와 별도 ETF/ETN 목록의 모든 페이지, 미국은 NYSE·NASDAQ·AMEX 전체 목록의 모든 페이지를 읽는다. 대상은 현재 키움 모의 실행기가 지원하는 현금 주식이다. 파생상품·장외시장까지 포함한다는 뜻이 아니다.
2. 전체 N에서 ETF/ETN·미지원 거래소·실행기에서 처리할 수 없는 코드를 정책 제외 E로 기록한다. 거래·자료 부재를 정책 제외로 바꾸지 않는다.
3. 대상 U=N−E 전부에 같은 공통 시세·거래량·등락률·시가·고가·저가 검증을 적용한다. 확인 V, 자료 부족 D를 기록하며 U=V+D와 N=E+U를 검증한다. 목록 자체가 불완전하면 이 수치는 null이며 관측된 일부 수만 별도로 표시한다.
4. 현재가가 당일 시가보다 높고 거래량이 있거나, 실제 연속 수집의 거래량 증가 속도가 직전 구간 대비 기본 1.5배 이상인 종목을 상세 검토 신호로 분류한다. 고정 상위 N개 제한은 없다. 첫 수집에 거래량 가속도를 만들지 않으며 서로 다른 두 구간이 확보된 뒤 계산한다. 과거 동시간 분모가 없으므로 RVOL은 null이다.
5. 신호 없는 종목은 `waiting`이고 `event_review=not_checked`다. 새 사건 경로 검토가 남아 있으며 규칙 탈락이나 매수 불가를 뜻하지 않는다. `candidate`도 자동 매수 권고가 아니다.

공통 수집 완료 `data_complete`와 AI 선정 완료는 별개다. 수집기는 `candidate_review_complete=false`를 반환한다. 뉴스·공시 수집, 기업 사건의 사실 확인과 목표가 산출은 이 모듈에 구현하지 않았다.

## 수집 API와 완결성

필드·요청은 [키움 공식 REST API 예제](https://github.com/Kiwoom-Securities/Kiwoom-REST-API/tree/953e5dbff123f437ab4d11a78a95191a685eb51f)를 기준으로 구현했다.

| 시장·자료 | API | 처리 |
| --- | --- | --- |
| 국내 목록 | `ka10099` | 시장 구분 0·10·50·8·60·70·90, 전체 연속조회 |
| 국내 공통 시세 | `ka10095` | 기본 50종목씩 `\|` 배치, 모든 대상 순회 |
| 미국 전체 목록 | `usa10099` | `stex_tp=%`, 모든 연속조회, 호출 간 최소 12.1초 |
| 미국 공통 시세·거래량 | `usa20570`, `usa20530` | 필터 없는 전체 조회를 목록과 대조; 결과가 잘려도 대상 수를 줄이지 않음 |
| 미국 조회 부족 보완 | `usa10101`, `usa20100` | 부족이 100종목을 넘으면 전체 공식 업종으로 대량 조회를 분할하고 남은 종목은 개별 조회 |
| 일봉·시간봉 | `ka10081/ka10080`, `usa06012/usa06011` | 상세 검토용 첫 페이지, 회당 최대 5종목, 30분 또는 60분 |

반복·없는 커서, 잘못된 연속조회 표시, 비어 있는 연속 페이지, 필수 시장 목록 누락, 상충 중복과 페이지 제한 도달은 완결로 처리하지 않는다. 기본 제한 10,000페이지·수집 1,800초는 장애 방지 한도다. 한도 도달은 미완료이며 후보 축소나 자료 부족의 자동 제외로 처리하지 않는다. 대량 조회 실패 시 그 조회의 부분 결과는 버리고 부족분을 보완한다.

원본 필드와 수신 시각을 보존한다. 국내 `dt`와 호가/체결 시각이 유효하면 원본 시각도 별도로 제공한다. 미국 대량 응답에 원본 시각이 없으면 `provider_timestamp=null`이며 수신 시각을 원본 시세 시각으로 만들지 않는다. 원본 시각이 없는 자료는 실제 지연 정도가 확인되지 않은 자료다. 신규 주문 전 기존 실행기의 최신 호가 검증을 추가로 거친다.

## 매시간 실행과 조회

데모 실행기의 주기 루프는 평일 국내 09:00~15:30, 미국 09:30~16:00 현지 시각의 매시간 회차를 시작한다. 미국 회차는 개장 30분 기준이다. 이는 읽기 전용 수집의 기본 트리거이며 휴장·조기 종료를 확인한 주문 세션을 대신하지 않는다. 수동 수집은 장전에도 가능하다.

1. `get_execution_status`에서 `execution_capabilities.market_scanner`의 지원 여부·버전을 확인한다.
2. `start_market_scan(market="KR" 또는 "US")`로 시작하고 `scan_id`를 보관한다. snapshot도 시작을 요청한다. 같은 회차는 재사용하며 진행 중인 작업은 중복 실행하지 않는다.
3. `get_market_scan`으로 상태를 다시 확인한다. `running` 동안 기존 보유 재평가·매도 관리를 진행한다. 종료된 미완료 작업은 필요하면 `force=true`로 다시 시작한다.
4. 같은 `scan_id`의 `view="candidate"`, `"waiting"`을 `next_offset=null`까지 읽는다. 페이지 `limit`은 1~500이며 전수 후보 상한이 아니다. `excluded`·`data_missing`도 검증·기록한다.
5. 일봉·30분/60분봉은 `get_market_context`로 조회한다. 첫 페이지 최대 200행과 원본 시간을 제공하며 현재 일봉·진행 중 시간봉을 완료 봉으로 단정하지 않는다. 필요한 이력이 없으면 부족을 기록한다.
6. Work가 사건 경로를 포함한 선정과 투자 가설 검토를 마친 뒤 최신 계좌·호가를 재조회하고 실제 지시를 제출한다.

기존 연결에서 새 도구가 보이지 않으면 MCP 도구 목록을 갱신해야 한다. 기존 snapshot의 첫 100행만 보고 전체 후보 검토를 완료했다고 하지 않는다.

## 신규 매수 차단과 보유 관리

최신 회차가 전체 목록·모든 대상 관측을 완료했고 동일 현지 거래일이며 자료 수신 경과가 기본 1,800초 이내여야 신규 BUY를 접수한다. 실행 직전에도 다시 확인해 오래되거나 미완료면 `waiting_market_scan`으로 대기한다. 대상 종목 자체도 확인된 공통 입력·당일 거래 증거가 있어야 한다. 전체 입력 확인이 AI 선정의 완결성을 자동 증명하지는 않는다.

수집 중·누락·재시작 중단·저장 실패는 신규 BUY만 차단한다. 계좌 조회·HOLD·SELL·REPRICE·CANCEL과 검증된 기존 목표 주문 관리는 계속 가능하다. 수집 결과로 실제 주문 수량·키·설정·원금 장부를 초기화하지 않는다.

## 적용과 로컬 보관

`market_scan` 설정 예제는 `config.example.json`에 있다. 기존 `config.json`에 없으면 기본값을 사용하므로 재초기화하지 않는다. 결과는 `runtime/market-scans`에 원자적으로 저장하며 기본 시장별 최근 3회와 참조 중인 완료 회차를 보관한다. 수집 도중 종료된 작업은 재시작 시 `interrupted`이며 매수 허가 자료가 되지 않는다. runtime 데이터는 Git에 올리지 않는다.

기존 V6 설치에는 빌더로 생성한 `money_fix_20261016_v7.py`를 Termux에서 실행한다. 기본 설치 위치는 `~/money-work/money`이며 다른 위치는 첫 인자로 전달한다. 설치기는 이전/적용 후 소스 해시, 자체 테스트와 재시작된 서버의 수집기 버전을 확인한다. `.env`, 실제 설정과 SQLite 장부를 유지하며 실패하면 소스를 복구한다. 설치 후 국내 수집을 읽기 전용으로 시작하고 진행 상태를 표시한다. 설치 성공은 실계좌 API 전수 수집 성공을 뜻하지 않으므로 N/E/U/V/D와 `data_complete`를 실제 확인한다. Git 업로드만으로 휴대폰 파일이 교체되지는 않는다.

```bash
python3 scripts/build_scanner_installer.py /tmp/money_fix_20261016_v7.py --baseline PRE_SCANNER_COMMIT
python /storage/emulated/0/Download/money_fix_20261016_v7.py
```

검증은 실제 주문을 내지 않는 fixture 기반 테스트다. 공식 API의 모의 서버 권한·실제 페이지 수·지연과 휴대폰 환경에서의 최종 동작은 적용 뒤 확인해야 한다.
