# money — Work 분석 / Termux 모의주문 실행기

Work가 종목·수량·매수 상한·목표가·즉시 청산 여부를 결정하고, Android Termux의 Python은 키움 REST API로 그 지시를 실행합니다. 프로그램 자체에는 종목 선정 또는 가격 예측 전략이 없습니다.

**현재 상태:** V6 실행기와 MCP 연결 서버입니다. 최신 `money_fix_20261016_v6.py`의 소스 변경을 반영해 미국 모의매수 현금 검증을 지원합니다. 운용 기준은 단기투자 전략 v2.0입니다. 소스 설치만으로 외부 AI 재평가 예약이 생성되거나 활성화되지는 않습니다.

## 반영한 운용 조건

- 국내·미국 합산 운용 원금 1,000,000원. 종목별 정확한 수량은 Work가 결정하며 현금 보유를 허용합니다.
- 최대 동시 보유 10종목. 전체 시장에서 점검할 종목이나 상세 후보의 수를 10개로 제한하지 않습니다.
- 정규장 매시간 전체 시장에서 신규 매수 가능성을 점검합니다. 매수 체결을 조회하면 해당 체결 수량의 최초 목표가 매도 지정가 주문을 냅니다.
- 매시간 Work가 모든 실제 보유의 투자 가설과 상승·하락 전망, 미체결과 시세를 재평가해 유지, 목표 상향·하향 또는 청산을 판단합니다. 일봉·완료된 시간봉을 중심으로 판단하며 5분봉은 실행 보조로 사용합니다. 필요한 자료가 실제로 확보됐는지 별도로 검증합니다.
- 새로운 지시가 없으면 임의로 다른 종목을 매수하지 않습니다. 검증된 거래일 세션 안에서 목표가 주문 관리는 실행기가 계속 맡습니다. 마감 시각만으로 보유분을 매도하지 않습니다.
- 고정 손실 금액·퍼센트에 따른 자동 손절은 넣지 않았습니다.
- 단기투자를 지원하며 고정 보유 기간을 두지 않고 다음 거래일까지 보유할 수 있습니다. 마감과 거래일 변경에 따른 강제청산은 없습니다. 기존 `close_buffer_minutes`는 신규 매수 마감 및 미체결 매수 취소에만 사용합니다. 기본 신규 매수 마감은 국내 마감 15분 전, 미국 마감 5분 전입니다.
- 국내 KRX 일반 주식, 미국 NYSE·NASDAQ·AMEX 일반 주식만 지원합니다. v0.1은 ETF/ETN의 별도 호가단위, 신용·미수·공매도·소수점 주문을 구현하지 않습니다.
- 실전 서버 주소나 실전 모드는 없습니다. `kiwoom-demo`는 `https://mockapi.kiwoom.com`에만 요청합니다. `paper`는 키움과 무관한 오프라인 테스트용입니다.

수익과 목표가 도달을 보장하거나, 수학적으로 최적인 포트폴리오를 계산하는 엔진은 아닙니다. 분석의 품질은 별도로 모의 운용 기록을 통해 평가해야 합니다.

## 구성

| 구성 | 역할 |
|---|---|
| Work 예약 작업 | 뉴스·시장·호가·차트 분석, 예산 배분, 시간 내 목표가 가능성 판단, 사용자 알림 |
| `get_trading_snapshot` | 키움 모의계좌의 현금·프로그램 보유분·주문 상태·호가·분봉을 Work에 제공 |
| `submit_trading_plan` | Work가 작성한 JSON 지시를 영속 큐에 저장 |
| Termux 실행기 | 개장 시 주문, 체결 확인, 목표가 매도, 취소 확인 후 주문 교체, 거래일 간 보유 유지 |
| SQLite | 원금·현금·보유·주문·체결 누계·처리한 지시를 재시작 뒤에도 유지 |

예산은 프로그램 전용 가상 원화 장부와 실제 계좌 주문가능금액 양쪽에서 확인합니다. 미국 주문은 계좌 적용 환율로 환산하며 V6에서 USD 현금 상한·미체결 매수 예약·수수료로 매수 가능 정수 수량을 보수적으로 계산합니다. 모의 미지원 `ust31490`을 호출하지 않으며, 이 계산을 증권사가 직접 확인한 종목별 무미수 가능 수량이라고 설명하지 않습니다. [V6 변경 설명](docs/us_cash_v6.md)을 참고합니다. 두 모의계좌 사이에 현금을 실제로 이체하거나 자동 환전하는 기능은 없습니다. 각 계좌에 필요한 모의 원화/외화 주문가능금액이 있어야 합니다. 손익 장부는 설정 수수료와 주문 시점 환율을 사용한 추정이며, 증권사 확정 손익과 다를 수 있습니다.

## Termux 설치

공식 [Termux 배포 안내](https://github.com/termux/termux-app#installation)를 따라 설치합니다. 이후 Termux에서:

```bash
pkg update
pkg install python git tmux cloudflared
git clone https://github.com/bigeatman/money.git
cd money/코드
python -m money.cli init
```

Python 3.11 이상이며 Python 외부 패키지는 필요하지 않습니다. `코드` 디렉터리에서 `python -m money.cli`로 실행합니다. 설정·키·장부도 이 실행 루트에 생성됩니다. 기존 휴대폰 설치 디렉터리는 Git 업로드만으로 이동하거나 변경되지 않습니다.

### 저장소 구성

실행 소스·테스트·설정 예제는 `코드`, 분석 전략은 `종목 선정 전략`, 일일 보고서는 `활동 내역`에 보관합니다. 실제 `.env`, `config.json`, `runtime` 장부는 업로드하지 않습니다.

1. 키움 [REST API 이용안내](https://openapi.kiwoom.com/intro/serviceInfo)를 따라 모의계좌와 모의 App Key를 발급하고, **휴대폰에서 키움에 접속할 때의 공인 IP**를 등록합니다. Wi-Fi/LTE/VPN 변경 후에는 이 IP가 달라질 수 있습니다. Cloudflare 수신 터널의 IP와 키움 접속 IP는 서로 다릅니다.
2. 키는 휴대폰에서만 입력합니다. GitHub 또는 채팅에 올리지 않습니다.

```bash
python -m money.cli credentials --market KR
python -m money.cli credentials --market US
```

3. `config.json`의 `broker`를 `kiwoom-demo`로 변경합니다. `fees`는 **초기 비용 가정**입니다. 국내 매수/매도 각 0.35%, 매도세 0.20%, 미국 매수/매도 각 0.25%, 미국 매도 부대비용 예비율 0.01%입니다. 실제 모의계좌 적용 비용과 비교해 수정해야 합니다. 미국 예비율은 정확한 현행 SEC·FINRA 요율을 뜻하지 않습니다. 비용은 Work의 판단 자료에도 전달합니다.
4. Android에서 Termux를 배터리 제한 예외로 설정하고 절전 앱 대상에서 제외합니다.
5. 별도 Termux 세션에서 프로그램을 실행합니다.

```bash
tmux new -s money
bash scripts/start-termux.sh
```

`Ctrl+B`, `D`로 tmux에서 빠져나와도 세션의 프로그램은 실행됩니다. 다시 들어가려면 `tmux attach -t money`입니다. 화면을 켜둘 필요는 없지만 휴대폰 전원·네트워크·Termux 프로세스는 유지해야 합니다. tmux와 wake lock이 Android의 강제 종료를 완전히 막지는 못합니다.

## Work 연결: 공유 호스팅 대신 휴대폰 MCP 서버

Python이 휴대폰에서 작은 연결 서버까지 제공합니다. Work는 이 서버에 접속해 계좌 데이터를 읽고 지시를 저장합니다. 별도 OpenAI API를 호출하지 않는 구조입니다.

먼저 다른 Termux 세션에서 개발용 HTTPS 터널을 시작합니다.

```bash
cloudflared tunnel --url http://127.0.0.1:8765
```

출력된 `https://...trycloudflare.com` 주소로 다음 명령을 실행합니다.

```bash
python -m money.cli mcp-url --public-origin https://YOUR-TUNNEL.trycloudflare.com
```

출력된 **전체 MCP URL을 본인의 비공개 MCP 연결 설정에 직접 등록**합니다. 이 URL은 연결 토큰이 포함된 비밀 주소이므로 공개 이슈·커밋·로그에 붙이지 않습니다. 인증 방식은 개발용 비공개 연결의 `None`이며, 서버는 URL의 충분히 긴 난수 토큰으로 접근을 검증합니다. 토큰을 헤더로 설정할 수 있는 클라이언트는 `/mcp` + `Authorization: Bearer ...`도 지원합니다.

ChatGPT의 Plugins에서 사용자 지정 MCP 서버를 추가하는 [공식 연결 안내](https://developers.openai.com/api/docs/mcp)와 [플러그인 연결/테스트 안내](https://developers.openai.com/plugins/deploy/connect-chatgpt)를 따릅니다. 계정·워크스페이스에 사용자 지정 MCP 연결 권한이 있는지 확인해야 합니다. 연결 후 **예약 작업이 실행되는 대화에서도 이 연결 도구를 사용할 수 있어야 합니다.**

개발용 Quick Tunnel은 재시작할 때 주소가 변경되고 가동률을 보장하지 않습니다. 처음 연결 검증용으로만 사용하고, 장기간 모의 운용에는 고정 호스트 이름의 터널을 권장합니다. 이 서버는 SSE 없이 JSON 응답을 사용하므로 Quick Tunnel의 SSE 미지원 제약을 피합니다. 이메일 PIN 인증 옵션은 비대화형 MCP 호출과 맞지 않습니다.

MCP 도구는 다음 세 가지입니다.

| 도구 | 용도 |
|---|---|
| `get_trading_snapshot` | `market="KR"` 또는 `"US"`, 후보 `instruments` 최대 10개. 기본적으로 실제 호가와 5분봉을 포함합니다. |
| `submit_trading_plan` | `plan` 객체를 접수합니다. 접수 성공은 체결 성공이 아닙니다. |
| `get_execution_status` | 각 지시·주문의 실제 처리 결과와 오류를 읽습니다. |

`get_trading_snapshot`에서 최근 체결을 먼저 동기화합니다. 계좌번호와 인증 키는 분석 결과에서 제외합니다. API가 반환한 차트의 첫 페이지와 원본 시간 표기를 전달하며 전체 이력 또는 지연 없는 시세라고 단정하지 않습니다.

## 전체 시장 점검의 구현 범위

이 실행기에는 전 종목 목록·공통 시세를 일괄 수집하는 스캐너가 없습니다. 기본 snapshot은 일부 지정 종목 조회이며 차트는 5분봉 첫 페이지입니다. 일봉·시간봉과 전체 시장의 데이터 확보를 자동으로 완료했다고 간주하지 않습니다.

`instruments`의 최대 10개는 호출당 조회 한도입니다. 전체 후보를 10개로 제한하는 규칙이 아닙니다. 전수 목록·공통 데이터·페이지 완결성과 단계별 입력/통과/제외/대기/자료 부족을 검증해야 하며, 전수 선정 미완료는 신규 매수 보류와 '선정 작업 미완료' 보고로 처리합니다. 확인 가능한 기존 보유와 미체결 관리까지 중단하지 않습니다.

## 예약 알림 연결 순서

1. `get_trading_snapshot`을 실제 모의계좌로 성공시켜 연결을 먼저 검증합니다.
2. Work에 `../종목 선정 전략/운용절차.md`의 분석 지침을 적용합니다.
3. 기존 예약을 확인해 국내·미국의 정규장 매시간 회차에 최신 단기투자 지침을 적용하고 중복 예약을 만들지 않습니다.
4. 국내 정규장 중 매시간, 미국 정규장 개장으로부터 매시간 재판단하는 예약을 추가합니다. 미국 시간대는 `America/New_York`를 사용해 서머타임을 반영합니다.
5. 휴장·지연 개장·미국 조기 종료 시간을 공식 거래소 자료로 확인해 매 거래일의 `session`을 작성합니다. 세션 정보가 없으면 프로그램은 새 주문을 내지 않습니다.

**모의계좌 연결과 정기 AI 재평가 예약은 별개입니다.** 예약의 실제 연결·활성 상태와 회차 결과를 확인하며, 소스 설치만으로 자동 분석·주문이 가동 중이라고 설명하지 않습니다. `../종목 선정 전략/운용절차.md`에는 연결 후 적용할 지침과 일정이 준비되어 있습니다.

## 지시 형식

`docs/plan.schema.json`을 참고합니다. 가격은 부동소수점 오차를 피하려고 문자열로 전달합니다. Work가 생성 시각·만료 시각·거래일의 개장/마감·거래소 달력 출처를 작성합니다. 만료는 생성 후 최대 60분이며 당일 마감보다 늦을 수 없습니다. 기본 매수는 정규장 지정가입니다.

국내 KRX 개장 30분 전부터 `preopen=true`와 `order_type=LIMIT` 또는 `MARKET`으로 장전 주문을 접수할 수 있습니다. 이 시간에는 호가 0을 이유로 차단하지 않으며, 최신 당일 기준가·상한가·하한가를 검증합니다. 시장가에서는 `buy_limit`이 증권사에 전송할 지정가가 아니라 허용한 가격 상한입니다. 당일 상한가가 이 한도를 넘으면 주문을 거부하고, 상한가×수량×매수 수수료로 공유 100만원 예산을 확보합니다. 실제 시가·체결 수량은 증권사 체결 응답으로만 장부에 반영합니다. 시가 상승으로 초기 목표가가 실제 비용보다 낮아지면 비용을 넘는 최소 호가로 조정합니다. 아직 전송하지 않은 장전 지시는 개장 시 만료되며, 접수된 주문은 계속 동기화됩니다. 장전에는 프로그램 주문의 취소도 가능합니다. 미국 장전·장중 시장가 매수는 지원하지 않습니다.

| action | 필수 추가 항목 | 의미 |
|---|---|---|
| `BUY` | `quantity`, `buy_limit`, `target` | 지정 수량 매수. 상한보다 호가가 비싸면 추격하지 않고 만료까지 대기 |
| `HOLD` | 없음 | 현 상태 유지 |
| `REPRICE` | `target` | 기존 목표가 매도 취소 확인 후 새 목표가로 교체. 손실 축소를 위한 낮은 가격도 가능 |
| `SELL` | `quantity=0` | 프로그램 보유분 전량을 시장가 청산. 기존 매도 주문 취소가 먼저 확정되어야 함 |
| `CANCEL` | `order_ref` | 프로그램이 낸 특정 미체결 주문 취소 |

새 BUY 지시는 아직 실행되지 않은 이전 BUY 지시를 대체합니다. 이미 증권사가 접수한 미체결 매수는 `CANCEL` 또는 `SELL`로 취소해야 합니다. 재매수는 새 plan_id로 명시해야 하며 프로그램이 수익 후 자동으로 재매수하지 않습니다.

프로그램이 산 수량만 청산합니다. 시작 전부터 계좌에 있던 주식이나 사용자가 별도로 산 물량을 전량 매도하지 않습니다. 계좌 밖에서 프로그램 물량을 수동 거래하면 장부와 잔고가 어긋날 수 있으므로 동기화 오류를 확인해야 합니다.

## 장애·복구

- 미국 모의 체결 확인은 실제 모의계좌에서 확인한 `ust21510`(당일 주문체결)과 `ust21050`(미체결)을 사용합니다. 모의 미지원 응답이 확인된 `ust21180`은 실행 경로에서 사용하지 않습니다. 새 매수 전 해당 거래일의 체결 조회를 검증합니다.
- 미국 모의 체결 조회는 당일 범위입니다. 이전 거래일의 미해결 주문을 현재 날짜의 조회로 확인했다고 간주하지 않습니다. 누락·상충 응답은 재주문이나 강제 체결 처리 대신 오류로 남깁니다.
- 미국 체결금액 필드가 제공되지 않으면 반환된 체결단가와 누적 체결수량의 곱을 장부에 반영하므로 반올림 차이가 생길 수 있습니다. 주문의 `fill_amount_basis`를 함께 확인하고, 설정 수수료로 계산한 전략 손익과 키움이 반환한 계좌 전체 실현손익을 구분합니다.
- 지시는 SQLite에 저장하고 중복 plan_id를 재실행하지 않습니다. 같은 ID로 다른 내용을 제출하면 거부합니다.
- 주문 의도를 **전송 전에** 저장합니다. 전송 후 응답이 끊겨 주문 접수 여부를 모르면 `unknown`으로 두고 재전송하지 않습니다. 이때 신규 주문은 중단됩니다.
- 취소 요청 직후 새 매도를 내지 않습니다. 체결/미체결을 다시 조회해 취소와 추가 체결을 반영한 뒤 잔량만 매도합니다.
- 체결 조회는 기본 5초 루프이며, API 조회·유량 제한 시간을 더한 지연이 있습니다. 매도 지정가는 매수 체결을 **감지한 직후** 제출됩니다. 실시간 체결 이벤트를 쓰는 밀리초 단위 프로그램은 아닙니다.
- 주문 번호가 확인되는 모호한 주문은 인증된 HTTP `POST /resolve`에 `{"order_ref":"...","broker_id":"..."}`를 보내 복구할 수 있습니다. 실제 주문의 종목·매매 구분·수량이 저장된 의도와 일치해야 합니다. 접수되지 않았다고 추정해 장부를 삭제하고 재매수하지 않습니다.
- 익일 보유분은 원금 장부·목표가와 함께 유지됩니다. 다음 거래일에는 공식 달력으로 검증한 새 `session`을 제출해야 목표가 주문 관리를 재개합니다(`HOLD`로 가능). 휴장일·오래된 세션으로 새 주문을 만들지 않습니다. 국내 당일 유효 주문은 원 주문일의 체결내역으로 추가 체결을 반영하고 만료를 두 번 확인한 뒤 잔여 보유 수량의 목표가 주문을 다시 냅니다. 내역이 없으면 만료·체결로 추정하지 않습니다. 미국 전일 미확정 주문은 당일 전용 조회 API로 해결할 수 없으므로 오류를 표시하고 해당 시장 주문 실행을 보류합니다. 마감이나 날짜 변경을 이유로 `SELL`을 제출하지 않습니다.
- 원금 장부를 매일 100만원으로 초기화하지 않습니다. 손실로 감소한 현금이 유지되고, 매도 체결 확인 후에만 재사용합니다.
- 주문이 있는 장부에서 `paper`/`kiwoom-demo` 모드를 바꾸거나 다른 모의 App Key로 계좌를 바꾸면 실행을 거부합니다. 이전 장부를 보관하고 별도 실행 디렉터리에서 새 장부로 시작해야 합니다.

프로그램 실행 중 상태 조회는 HTTP `/status`를 사용합니다. 중지 상태에서는 `python -m money.cli status`를 사용할 수 있습니다. 키움 실서버에는 접속하지 않으므로 모의 접속만으로 서비스가 자동 해지되는 키움 정책은 별도로 확인해야 합니다.
